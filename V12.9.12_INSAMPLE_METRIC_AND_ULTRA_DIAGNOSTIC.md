# v12.9.12 — in-sample metric sync + ultra-stable residual diagnostic

## Dashboard regression fixed
After aggregate operational charts were switched to bottom-up sums, the current-selection
in-sample KPI was still rebuilt from the displayed aggregate series. Aggregate rows do not
have one meaningful `rls_metric_eligible` flag, so the metric filter could remove the whole
in-sample interval and incorrectly return `wMAPE=0%, BIAS=0%` even when the chart visibly
differed.

The dashboard now reads the official current-selection in-sample metric from
`metrics_in_sample.parquet`, exactly analogous to OOS from `metrics.parquet`. The official
bottom-up definition is unchanged.

## Statistical continuation
v12.9.12 adds a diagnostic-only ultra-stable gate on top of the existing v12.9.11 Sec23
Value residual evidence. It requires 100% historical wins, positive worst/recent behavior,
minimum median/p25/weighted gains, no bias deterioration and <=3% volume exposure. It does
not write to `valuehat` or `yhat`; v12.9.10 productive policy remains frozen until the new
diagnostic has been run and reviewed.
