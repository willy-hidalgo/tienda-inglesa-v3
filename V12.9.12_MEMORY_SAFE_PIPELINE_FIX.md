# v12.9.12 — memory-safe pipeline fix

Technical-only patch. `APP_VERSION` remains **12.9.12** and forecast algebra / selection policy is unchanged.

## Problem observed
After section 1 completed the pooled LightGBM challenger, the process failed while trying to allocate ~10 MB. The pooled shape context was still retaining all precomputed feature blocks, target-local base forecasts, and corrected forecasts while the wide final leaf frame and production invariants were being built.

## Changes
- Added `PooledLGBMShapeContext.release_origin()` to discard corrected/base forecasts immediately after each leaf candidate is materialized.
- Added `PooledLGBMShapeContext.close()` to clear the remaining feature/cache frames after OOS and forecast-only candidates are materialized.
- `leaf_v12.py` closes the pooled context and triggers `gc.collect()` before the wide final joins/invariants.
- Added `tests/test_v12_9_12_memory_release_contract.py`.

## Invariants
- No changes to wMAPE/BIAS algebra.
- No changes to model fitting, LightGBM hyperparameters, selection gates, candidate forecasts, or production promotion logic.
- `APP_VERSION` remains `12.9.12`.
